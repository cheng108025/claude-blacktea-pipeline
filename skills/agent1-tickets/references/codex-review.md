# 外部覆核（可選 🔧：先問使用者要不要）

1. 計劃書與工作單都寫好、自我稽核 7 項做完後，**詢問使用者**：「要不要用 Codex（OpenAI 的 AI 工具）獨立檢查一次計劃內容？**提醒：這需要你有 Codex 的付費帳號**，而且電腦上要裝好 Codex CLI 並登入過；沒有的話跳過就好，不影響流水線。」
2. 使用者說不要、或 `codex --version` 跑不動 → 跳過，在自我稽核結果標一句「外部覆核：未執行（使用者跳過／codex 不可用）」。
3. 使用者要、且確認可用 → 用**非互動模式**請它獨立審查兩份文件，並要求它替每個問題**分級** 🔧：

   ```bash
   codex exec "你是獨立審查員。請閱讀 .pipeline/plan/01-requirements.md 與 .pipeline/plan/02-workplan.md，列出：(1) 規格模糊或矛盾處 (2) 工作單相對規格的缺口 (3) ticket 做法不可行或風險處。只輸出問題清單，每項附出處，並標分級：【重度】一定要修，不修會有問題（照著做會做錯、做不出來或互相矛盾）；【中度】需修改，但不影響功能；【輕度】不修功能不會有問題，但可能讓整體執行效率變慢。"
   ```

4. 把 Codex 的發現當**第二意見**逐項判讀：先判真偽（誤報 → 忽略並記一句原因），成立的**由你最終定級**（Codex 給的分級只是建議，你可以調級），然後照分級處理：

   | 分級 | 定義 | 處理方式 |
   |---|---|---|
   | 重度 | 一定要修，不修會有問題 | **必須處理完才能進 Phase E**：併入待問清單回頭問使用者，或補預設寫進決策紀錄——不准帶著重度缺口交棒 |
   | 中度 | 需修改，但不影響功能 | 逐項修正文件；判斷不值得改的，要在決策紀錄寫明「不改的原因」，不准默默忽略 |
   | 輕度 | 不修功能不會有問題，但可能讓整體執行效率變慢 | 順手能改就改；不改的集中記進決策紀錄的「輕度觀察」清單，留給建造者參考 |

   **Codex 的意見不能直接改文件**——最終判斷權在你，處理結果**依分級分組**隨自我稽核一起展示給使用者。
