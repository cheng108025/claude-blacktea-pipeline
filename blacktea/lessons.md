> 規則：每段落上限 15 條 🔧；滿了必須合併同類或刪過時，不准無限追加。

> 手動修改沒問題——這是你的經驗庫，復盤官只是幫你維護它。
>
> 交換：`/blacktea_retro 匯出` 產出可分享檔（段落結構與本檔相同，檔首多一個 `blacktea-lessons-export` 標頭）；

## 通用（所有角色都讀）

- [2026-08-27→2026-09-29·gold] 「新增 N 個測試」≠「守門厚度 N」、「一次性 diff 通過」≠「有東西守著」——任何「不變／守住」類 DoD 一律用變異驗證（把修復還原，看哪個測試轉紅）才算數；斷言不得比對它要驗的那個 production 常數本身（會恆真），期望值一律寫硬編碼手算值（為什麼：同型缺陷累計五犯；硬編碼期望值的票兩項變異雙雙轉紅，同輪只改字面的票 79 passed 零轉紅｜證據：V-042、V-052、V-058、V-063、V-067、V-085、V-101、V-123、V-129、V-149）
- [2026-08-27·gold] 專案若依安裝路徑固定解析資料目錄，cwd 隔離無效——真實跑 run 類動作前必先備份「檔案＋DB 列」三件套並 md5sum 驗還原（為什麼：兩輪都覆寫了正式報告與 DB｜證據：T-Rev05 自動決策 2、T-Rev06 05-e2e 事件）

## 訪談官（agents/agent1_plan.md ＋ skills/agent1-interview／spec／tickets）

- [2026-08-27→2026-09-29·gold] DoD 不得用行數、案例數當品質代理（誘發指標操弄），**也不得寫死會隨時間變動的當下實際值**（表列數、檔案數、測試總數）——改成行為證據或相對基線（重構前後回應 diff 為空、變異轉紅、前後列數不變、新增 ≥N）（為什麼：CSS 被壓成 173 字元單行湊「淨減恰好 90」；寫死的數字在開工時早已過期，害檢查員對正確的實作判 FAIL｜證據：V-057、T-Rev09 偏離 1、T-Rev20c DoD 寫死 reports=29 實際 34、T-Rev12c ≥236 實際 230、T-Rev12d ≥240 實際 234）
- [2026-08-27·gold] 票面「既有測試零改動」不可與同票「改行為」並列；出票前把 DoD 逐條對照做法欄找互斥（為什麼：三張票都因此讓檢查員替票面擦屁股｜證據：T-Rev07a 索引、T-Rev06a 偏離、T-Rev05 偏離 3）
- [2026-08-27·gold] 票面引用的文件位置、資料表狀態要先 grep／查 DB 驗證再寫（為什麼：「該句在每日排程.md」實際在 Dashboard.md；「這些列由測試產生」實為真實資料｜證據：T-Rev08b 偏離 1、2；V-068）
- [2026-09-29·gold] 會耗額度或需真實外部服務的路徑，出票時要**成對**寫「真實步驟（使用者手動驗收、標未實測）」＋「離線替身步驟（必跑）」（為什麼：政策禁打額度，沒有替身那條路徑就永遠零自動守門｜證據：J2c-2a／2b／2d，14～16 三輪該路徑皆未實測）

## 建造者（agent2-build）

- [2026-08-27·gold] CSS／HTML 註解會原樣輸出到頁面——註解內不得出現 class="…"／id="…" 字面，否則靠字串定位的斷言恆真（證據：V-049）
- [2026-08-27·gold] 背景執行緒狀態機：鎖的清除放 finally、最外層捕 BaseException；錯誤字串先遮罩再截斷（為什麼：狀態永久卡 running、半截金鑰外露｜證據：V-046、V-043、V-006）
- [2026-08-27·gold] 改變資料流（誰傳什麼給誰）後，grep 所有文件裡的舊呼叫寫法——資料流圖是最會說謊的文件；票面列了幾份文件就逐份勾（證據：V-066、V-065）

## 稽核員（agent3-review，含票級檢查與品質檢查）

- [2026-08-27·gold] 變異驗證禁用 git checkout／git stash：改壞前先 git diff 存快照，用 sed／Edit 改壞再還原，結束後 md5sum 對照（為什麼：同型事故兩輪各一次，把整票改動清空｜證據：T-Rev06b、T-Rev08b 流程瑕疵）
- [2026-08-27·gold] 對「逐字不變」「既有行為不變」類 DoD，不看測試名，直接破壞契約跑全套；全綠即開發現（證據：V-067、V-063、V-054）
- [2026-09-29·gold] 修復批次視同新票做變異驗證；Medium／Low 若走「調度員親自核對」取代一輪稽核，至少抽一項做獨立複核（為什麼：修復輪自己會引入新缺陷——修復輪新增的函式零守門，是靠下一輪獨立複審才抓到；另一輪修文件時把錯的 CLI 範例複製進 README｜證據：V-025、V-026、V-076～V-079）

## 實測員（agent4-run）

- [2026-09-29·gold] 替身要打在被測邏輯「**之下**」的邊界（替換底層 CLI／HTTP 呼叫，不要替換整個含被測邏輯的函式）（為什麼：替換整個函式會連帶跳過它內部那段正要驗的保險，測出假陰性｜證據：T-Rev19 實測員自曝 monkeypatch 整個 run_websearch）
- [2026-09-29·gold] 清理測試資料禁用條件式 `DELETE WHERE date=X`——同一鍵值可能有測前既存的時間序列列；改「整庫備份 → 逐列還原」（為什麼：誤刪 7 列既存籌碼資料，靠完整備份才復原｜證據：T-Rev18 實測資料事故）
- [2026-09-29·gold] 整檔 md5 不是有效的還原判據（常駐服務的心跳會改檔）——改逐表列數＋逐列逐欄比對，心跳造成的差異刻意不還原（為什麼：排程設定表每分鐘寫入，md5 必然漂移，會誤判成沒還原乾淨｜證據：T-Rev18、T-Rev20 還原判定）
- [2026-09-29·gold] 改到會被**長駐服務 in-process 載入**的程式後，要在「使用者實際在跑的那個行程」驗證，或在交付訊息明確要求重啟（為什麼：測試全綠、CLI 正常，使用者按下按鈕卻仍走舊碼｜證據：T-Rev18／19／20 三輪交付時 dashboard 行程啟動時間都早於程式 mtime）

## 流程與總指揮（blacktea_plan／blacktea_change／blacktea_retro／skills/blacktea-dispatch）

- [2026-08-27→2026-09-29·gold] 變更官改了任何契約（API 回應、port、日期規則、**數字類契約**如區塊數／來源數／表列數）後，grep 整份規格書的驗收清單與 docs／README 找同類殘留再 commit（為什麼：同型第四次復發——一輪裡 10 項文件殘留、其中四項數字是錯的，實測若逐字照讀會對正確的實作判 FAIL｜證據：V-055／Q-07、Q-14、Q-17、V-138～V-146、V-151）
- [2026-08-27·gold] 連續 ≥2 輪增量實測後下一輪派全旅程——舊 bug 只有全旅程抓得到（證據：E-001 於 T-Rev07 全旅程發現，非該輪引入）
