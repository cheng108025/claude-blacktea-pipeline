# 流水線共通執行契約

各角色開工讀本檔適用段落與專案 `.pipeline/plan/run-policy.md`；沒有政策檔時按總指揮的失敗出口處理，不自行補授權。

## 政策與安全邊界

- 使用者本次明確指示優先，其次是專案政策、引擎規則、經驗包。經驗包不新增授權；衝突時保留證據，採政策指定動作。專案保護的服務、資料、排程與外部額度限制適用建造、檢查、稽核、實測、總指揮與主對話。
- 需求問題依 run-policy 的模式處理：無人值守＝記待裁決、跳過受影響部分並繼續；遇事停下來問＝交回主對話。經驗包的「先問使用者」不能自行改寫無人值守政策。
- 驗證指令若會碰受保護資源，不照字面冒險執行；改用行為等價的隔離路徑、記錄差異。無法等價驗證就標未驗並走失敗出口，不當 PASS。
- 不在摘要、證據或報告貼出機密原值；只記檔案、規則類型與 commit。

## 票面與歸檔查詢

找票先查 `plan/02-workplan.md`；不在其中就 grep `plan/archive/INDEX.md`，讀 `archive/tickets/<票號>.md`。依賴、修復批次的原票 DoD 與整體檢查抽驗均同此規則；只讀相關票。索引內的票視為已完成，不要求重新在 02 打勾。需要決策時只查 `archive/01-history.md` 對應 Dnn；舊專案尚未歸檔則查 01 的決策紀錄。

## 規格版本與關卡計數

- 主對話每次定稿都在 01／02 檔首寫相同的 `規格版本: <唯一值>`（例如 `plan-20261024-140301-a1b2`）。同日兩次修訂也必須不同；定稿日期只供人閱讀。打勾、歸檔與補索引不改規格版本。
- 舊工單沒有版本：主對話或調度在開工時補一次；已存在且含未提交實作時，只補版本欄，不把實作夾入 plan commit。舊報告僅有日期時不推斷版本相同，記「舊版基準」並由呼叫方明定本次版本與計數起點。
- 報告寫「規格版本」「本輪稽核／實測執行次數」「計入額度的次數」「範圍」。同一輪資料夾、同一規格版本才接續計數；換版本歸零。agent4 退回的稽核與視覺修復重測依原政策不佔額度，但執行紀錄仍保留。
- 計入額度達上限而仍 FAIL 就走失敗出口，不多跑一輪才比較「超過」。無人值守可依既定政策跳過／帶已知缺口前進，但不把失敗寫成 PASS。
- **次數不決定範圍**。首次全案／變更增量／修復複審由呼叫方明示；新資料夾的第 1 次變更稽核仍是增量。複審與變更不因「第 1 次」重新跑全案或外部覆核。

## 報告搜尋與發現編號

- 找上一份 04 或 05：按輪資料夾數字由近到遠找最近**存在的該類報告**，可跳過沒有報告的小修輪；不能只找小一號資料夾。沒有任何前報告就記「無」，不捏造。
- 開 V／E／U 新號前，對所有 `rounds/*/04-verify-report.md`、`rounds/*/05-e2e-report.md`（含目前輪；舊案另含頂層 04／05）以指令取各類的最大數字＋1；沒有該類 ID 才從 001 開始。不靠記憶、不只讀上一份報告、不全文載入證據。
- 主指揮先查號並把 V／E／U 最大值與最近報告路徑傳入 prompt；產號角色寫報告前再核對一次。既有重複 ID 不回頭重編，引用時加輪名，另記異常；新號必須大於全域最大值。

## 修復批次識別

調度每次派批次先分配 `<F> = fix-<來源>-<報告輪次>-<批次>`；來源為 `audit`／`e2e`／`visual`。同來源同輪次的批次號取現有紀錄最大值＋1（包含同一報告後來追加的修復）；只有明確重試同一批才重用 `<F>` 並追加紀錄。所有 build-log、ticket-checks、一般輸出與 red log 用同一個 `<F>` 前綴。既有舊檔名不搬不覆寫，續修舊批次以指示給的識別碼為準。

## 隔離驗證與紅燈重建

- 調度派票／修復批次前記錄完整的 `基準 SHA`（當時 `git rev-parse HEAD`，固定位於 state 與索引）；同一張票重試沿用原基準。不能等檢查時才拿當下 HEAD 當開工版本。舊在途票缺 SHA 時由調度查出可靠基準，查不出就記 INCONCLUSIVE（基準缺失），不得猜。
- 票級檢查先等該波建造者全部回報，再由調度固定受檢快照；從副本驗票，不讓其他票的半成品混入判定。調度保留各票檔案擁有權清單，核對副本內的變更只屬於受檢票及必要、已通過的依賴；建造者仍不執行 git，需 Git 匯出時由調度提供。
- 紅燈重建、變異一律只改隔離副本。副本須含受檢實作、新測試與未追蹤新增檔，不複製正式 `.env`／資料；共用唯讀依賴可以連結，但被覆寫的程式與測試不得用 symlink／hardlink 指回原件。
- 先在副本跑綠燈；再用 `git show <基準SHA>:<實作路徑>` 的內容還原副本中的舊實作，新測試保留。本票新增且基準不存在的**實作檔**暫移到副本外；不移走新測試。紅燈必須來自指定新行為的斷言；相依缺漏、匯入失敗、服務沒起來等環境錯誤不算證明。若基準不存在公開介面，記限制並改用能針對新行為的變異驗證，做不到就 INCONCLUSIVE。
- 一次變異一處，驗後還原副本並再跑綠；前後用包含新增檔的 SHA256 清單核對正式工作區，確認本次驗證未改動原件。git diff 不涵蓋未追蹤檔，不能單獨作還原證明。副本中斷留髒不會污染正式工作區；續跑丟棄該副本並重建。

## 測試服務生命週期

1. 開工先依專案政策，用 `ss`／`ps` 等檢查 port、行程歸屬。既有服務不可直接拿來測，也不可只因佔 port 就殺掉；屬使用者或歸屬未知時換空閒 port 與隔離副本，不發 HTTP 探測受保護服務。
2. 背景啟動自己的服務，紀錄 PID、行程啟動時間、命令、cwd、port、資料與輸出路徑到本任務的 evidence（可另存任務專用 PID 檔，不能覆寫其他任務的 PID）。健康檢查設連線及總逾時，確認回應來自這個副本；啟動失敗不得把既有回應當成功。
3. 啟動與清理盡量放同一個非互動腳本，設 EXIT／INT／TERM trap；退出前核對 PID、啟動時間、cwd 仍對得上本次紀錄，再終止自己的行程及已確認的子行程。PID 不符或歸屬未知就回報，不 kill。禁用 `fuser -k <port>/tcp`、廣泛 `pkill`、僅憑舊 server.pid 殺行程。
4. 收尾用 `ss` 檢查 port 是否釋放；仍被佔用先識別擁有者，只能處理本次擁有的行程。不能為了「確認釋放」又對受保護服務發 HTTP。

## 文件殘留與除錯掃描

文件殘留自查必須有「適用／不適用及原因」、正控制、舊字面與相關標題的查詢、逐份處置結果；使用固定字串查詢（如 `rg -n -F -- '<舊字面>' docs/ README.md`），缺目錄應按專案實際文件路徑調整，不把讀檔錯誤當零命中。程式除錯殘留只掃實際 source 根目錄（包含根目錄程式檔），排除 `.pipeline/`、`.git/`、依賴、虛擬環境、證據與生成物；文字紀錄中的除錯標記不是執行殘留。記下範圍、指令、輸出及退出碼；搜尋工具出錯不算通過。

## 完工歸檔（建案階段五、變更步驟七共用）

1. 先寫本輪報告與 FINAL-REPORT 總覽，尚不 commit。只歸檔已通過、已 commit 的票（建案含全部已完成 T01～Tnn／T-Rev，變更含本輪完成票），保留未完成票；既有歷史不用為本次維護重寫。
2. 票全文原樣移到 `plan/archive/tickets/<票號>.md`，相關共同說明另存檔；補 INDEX 每票一列（票號／標題／功能／決策／commit／異動檔案）。commit、檔案與 Dnn 分別從 git、票面及決策交叉核對，不靠票名一定含 Dnn 的假設。來源的票段、總表與覆蓋對照相關列移走，02 保留現行共用契約與未完成票，更新歸檔提示與目前票數。舊非票面總表需要保留時移到 `archive/02-workplan-other.md`。01 的歷史決策／問答／已結案變更摘要移到 `archive/01-history.md`（沒有就建），01 留章節指引、最後 Dnn 與現行規格；不能把現行行為契約一起搬走。
3. **先驗副本相同與索引可回查，再移走來源**。目標已存在時比對全文，相同就視為已搬，不同就保留兩邊並回報歸檔衝突，不能覆蓋。重跑不重複加 INDEX 列，不重複搬歷史；中斷時依實際工件接續。
4. 把本輪「T-RevNN 進度」（如有）、**建造進度**、已結案自動決策與已決待裁決列，原樣追加到 `state-history.md` 的本輪區段；確認保存後移走來源。重複的建造進度段也都歸檔，不只搬最後一段。檔首夾帶的舊輪摘要也搬走。
5. state 只留目前狀態、未決裁決、未結案自動決策／未完成票、push 暫停／延後與待推基準、復盤檢查點；有在途任務時不能當完工歸檔。不得移走未決問題或尚未解除的 push 暫停。
6. 精確 stage 本輪報告、FINAL-REPORT、02、archive 新增／更新檔（以及本輪確實異動的 01），**最後一次單 commit 一起提交**。state／state-history 不入版控。核對 git status，不能帶入使用者原有修改；完成狀態在提交成功後才落地。commit 或歸檔失敗時保留可續跑狀態，不宣稱收尾完成。
