由 agent1 準備步驟後 Read。本技能只訪談，不開票、不派建造者。

1. 先讀使用者已給的內容與現有專案，確認目標、使用者、規模及技術限制。能自查的事實自行查證。
2. 只問會影響產品行為、資料、權限、部署或返工成本的決策。每轮至多4個互相獨立的問題；有分支的先問父題，收到答案才問子題。
3. 問題用一句影響說明＋2–4個具體選項，標建議與主要代價；只有難理解時才補例子。不要求每題都寫完整教學。
4. 頁面與流程：有哪些頁面（CLI 則是指令與輸出）、主要操作怎麼走、頁面怎麼跳轉。每個專案都要問清楚，規格書「頁面清單與流程」章靠它。
5. **必問——視覺定調**（每個專案都問；單獨一輪，排在技術路線之前，因為它決定 UI 樣式方案），4 題全選擇題：
   1. 風格原型：(a) 極簡工具風——留白、細邊框、灰階加一個強調色，像 Linear／Notion（推薦自用工具與後台）；(b) 資訊密集儀表板——表格與數字為主、緊湊、側欄導覽；(c) 消費型活潑——大圓角、鮮明色彩、卡片與插圖。
   2. 亮／暗：亮色／暗色／跟隨系統（預設亮色）。
   3. 主色：給 4 個具體色票（例：藍 `#2563eb`、綠 `#16a34a`、紫 `#7c3aed`、中性黑 `#111827`），可自填。
   4. 參考網站或產品（開放題，可空）。
   答案寫進規格書「設計系統」章的視覺定調表；使用者說「你決定」→ 預設 (a)＋亮色＋藍，一樣讓他看過。沿用使用者已指定的設計。
6. **必問——執行方式**（每個專案都問；排在技術路線之前，它決定 T01 檢查什麼、要不要容器化票、README 啟動指令）。Phase A 已明說就填「已確認」不再問。一題二選一，用他的專案舉例：
   - (a) 本機直接執行（推薦自用小工具）：零額外安裝、啟動快、除錯直接；代價是換機器要重裝環境。
   - (b) Docker 打包：`docker compose up -d` 一鍵起、在哪都一樣，適合交給別人或部署；代價是要先裝 Docker、建映像較慢、除錯多一層。
   出題前先查 `docker --version`、`docker compose version`，沒裝就把「要先裝 Docker Desktop 並開 WSL 整合」寫進 (b) 的代價。選 (b) 在同一輪補問：對外 port、哪些資料掛 volume（資料庫、上傳檔、報告）、機密怎麼進去（預設 compose `env_file: .env`，不烙進映像）。「你決定」→ 預設 (a) 並記決策紀錄。純 CLI 不要求 HTTP。
7. 技術路線：你先提出一張分層技術棧表再問（前端／UI 樣式方案／後端／資料庫／測試框架／執行方式，每列附為什麼適合與一句替代取捨；執行方式列照第 6 步答案填）。UI 樣式方案依視覺定調與前端框架選，必須 npm 可安裝、不靠執行期 CDN。使用者授權你決定就採合理預設並記錄，不再逐層確認。
8. 每輪把答案與預設寫 `01-requirements.md`（DRAFT），標記仍需裁決的問題。最多8輪仍有重大缺口時集中列出：補答、授權預設或暫停；不能偷偷猜產品契約。

出場條件：目標與本版範圍清楚、適用的資料／權限／外部契約已定義、主要旅程有具體預期結果，且沒有會阻礙開票的重大問題。不以主觀9分取代契約檢查。可逆的內部實作細節交建造者決定。

使用者提前要求開工：整理已授權預設及缺口，仍須通過規格與工單檢查。完成後回 agent1，下一步讀 agent1-spec。
