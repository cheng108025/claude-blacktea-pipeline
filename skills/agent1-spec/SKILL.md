## 寫法

- **表格優先**：能列成「項目 × 屬性」的內容（欄位、端點、錯誤碼、流程步驟、對應規則、邊界、資安規則、決策）一律用表格。使用者看 HTML 確認，表格最好掃讀。
- 第一章固定是「缺口總覽」：評分現況、用預設帶過的決策編號範圍、省略章、N/A 面向、已知風險與對策；有外部覆核時依重度／中度／輕度列處理結果與「判定不改」的理由；改版時加「第 N 版變更摘要」。
- 產品契約不可留「待定」：只能是「已確認」或「預設（理由，可改）」。內部實作不必逐函式指定。
- 當例子的計算值（相似度、星期幾、對比值、像素位置）用指令算出再寫，不手寫。
- 寧可整章省略，不准寫一半；省略的章在決策紀錄記一句原因。章名是下游契約，不可改。

## 八個必備章＋條件章

| 章名 | 下游誰用 |
|---|---|
| 專案概述 | HTML 檔名的專案名稱、成功條件 |
| 功能清單（含「本版不做」） | 票的所屬功能、稽核架構對照；每項有穩定 F 編號 |
| 技術選型 | 建造者的套件與執行方式依據 |
| 專案資料夾結構 | 建造者檔案放置、稽核亂放檢查 |
| 頁面清單與流程 | 驗收清單一致性、設計系統狀態矩陣的頁面範圍 |
| 設計系統 | UI 票、建造者前端守則、實測員視覺檢查的唯一依據 |
| 全域驗收清單 | 實測員的唯一劇本 |
| 決策紀錄 | 使用者確認預設值的依據 |
| 資料庫相關／介面契約／邊界條件與錯誤處理／資安與權限 | 適用才寫 |
| AI相關 | 有用 AI 模型／工具才必備 |

## 各章要點

1. **技術選型**：開頭放分層技術棧表 `分層｜用什麼（名稱＋版本）｜為什麼｜來源（已確認／預設）`，就是訪談技術路線那一張；不適用填「N/A：原因」。表後寫關鍵套件、版本、port、測試。「執行方式」小節不可省：本機寫背景啟動指令、port、健康檢查；Docker 另寫基底映像 tag、`主機:容器` port、volume 清單（主機與容器路徑）、機密注入（預設 `env_file: .env`）、健康檢查、`.dockerignore`（至少 `.git`、`.env`、依賴目錄、`.pipeline/`）。CLI 記命令與退出碼。
2. **專案資料夾結構**：樹狀圖列主要目錄與檔案，每項一句放什麼。
3. **資料庫相關**：「資料表總覽」表 `資料表｜存什麼｜為什麼需要｜保留期限`；每表一節欄位表 `欄位｜型別｜必填｜預設｜說明`（主外鍵寫在型別欄），表下列唯一限制與索引；非關聯式儲存用 `檔案｜格式｜說明`；用 SQL 的章末放與欄位表一致的建表 SQL。另寫檔案位置／連線變數、保留與清除、種子資料、外部同步規則。技術選型只管選哪個產品，這章管存什麼。
4. **介面契約**：Web/API 依序寫「共通規則」表、「端點總覽」`#｜方法｜路徑｜用途｜使用頁面`（A1、A2… 供工單與驗收引用）、共用型別欄位表與驗證規則表、每端點請求／回應欄位表、「錯誤碼總表」`錯誤碼｜HTTP｜出現在｜何時｜message 原文`、多步驟流程 `步驟｜動作` 表。CLI：每指令參數表＋輸出格式＋退出碼表。
5. **AI相關**：怎麼呼叫（CLI／API、背景或互動、逾時）、每個呼叫點用哪個**完整模型 id**（不寫會漂移的別名）、費用性質與頻率、失敗處理。不用 AI 就省略並記決策。
6. **頁面清單與流程**：每頁用途、上面有什麼、怎麼跳轉；CLI 寫指令與輸出流程。
7. **設計系統**（每個專案都要；沒有畫面時縮成輸出格式與文案規則，並記原因）：
   - 視覺定調表（訪談答案原樣）。
   - 「視覺樣本」：內嵌 HTML 區塊（`<div class="ds-sample">` 含 scoped `<style>`，HTML 檢視版會直接渲染），亮暗兩面板並排：色票、按鈕各變體、輸入框各態、徽章、本案主要卡片與特有元素、Toast、錯誤框、字級。只用下方 token，前一行註明「建造者以 token 表為準」。
   - token 表 `token｜用途｜亮色｜暗色`；文字色與實心底色分成不同 token（例 `--link` 與 `--primary`）；字級、間距、圓角、陰影、字型堆疊（含 CJK 後備）另列 `類別｜值`。
   - 對比驗算：所有文字／底色組合（亮暗兩套）用 WCAG 相對亮度公式以指令算，全部 ≥ 4.5:1 才定案，表下寫最低值；資料自帶顏色的元素規定取白字與深色字中對比較高者並舉 2～3 例。
   - 版面骨架、實際用到的元件與變體、每頁**適用**狀態矩陣（每格寫畫面與文案）、無障礙基本、UI 原型路徑。靜態頁不需要空資料／loading／Toast；不強制完整元件庫。長文字折行依設計與可讀性決定。
8. **全域驗收清單**：J 編號旅程，每條寫角色、前置資料、具體步驟、測試輸入、可判對錯的預期結果與驗證方法（哪個網址／指令／畫面操作）；數值預期用獨立基準。頁面／API 列表與功能清單、介面契約、頁面清單完全一致；邊界行為在旅程中定義一次，其他章引用穩定 ID。
9. **決策紀錄**：`編號｜決策｜來源｜理由` 表，含所有預設、實作偏好（未驗證）、省略章與原因。文末放問答紀錄。
